Before you start

SimonSays is a small server you run on your own machine. On Windows and Linux, a download and its installer do it all; on an Android phone, one command. By hand it is four moves everywhere: get Node.js 22 or newer, download the app, run npm install, then run npm run serve. Plan on 15 to 30 minutes the first time, most of it waiting for downloads.

Pick your path

The simplest setup runs SimonSays on the same PC as OBS. Any other machine on your home network works too: OBS then points at that machine's address instead of localhost.

What you need

  • Node.js 22 or newer. The app refuses older versions. Check with node -v.
  • The app itself, from the public repository github.com/Bastian-Alvarado/SimonSays. Download the ZIP or clone it with Git.
  • Git (recommended). Not required, since the app updates itself, but it makes downloading and updating one command each.
  • OBS Studio 28 or newer on the computer you stream from. Version 28 is the first with the WebSocket server built in.
  • About 1 GB of free space for the app and its dependencies, plus room for your sounds and pictures.
  • The accounts you stream from: Twitch, YouTube, TikTok, and Discord or Spotify if you use them.

Words used in this guide

  • Terminal: the window where you type commands. Each command goes on its own line; press Enter after each.
  • App folder: the folder you downloaded SimonSays into. Every command below runs from inside it.
  • The server window: the terminal running npm run serve or npm start. It is the app. Closing it stops SimonSays; closing the browser does not. Installed, there is no such window: it runs from the tray, or as a service.

Windows

On Windows 10 or 11, one installer does it all: it brings everything SimonSays needs, Node.js included, and asks for no administrator. Use the PC that runs OBS unless you have a reason not to.

1

Download the installer

Download SimonSays-Setup.exe, the latest release.

2

Open it

Windows protected your PC? The installer is not signed yet, so SmartScreen does not know it. Click More info, then Run anyway.

Pick English or Español: SimonSays starts in that language. Tick a desktop icon or Start SimonSays when I sign in to Windows if you want them, then Install. It goes in your own user folder, so nothing asks for an administrator.

3

Find it in the tray

SimonSays runs from an icon by the clock (under the ^ if Windows hides it). Click it to open the dashboard; right-click it to restart, open the logs folder, start it with Windows, or quit. Closing the browser does not stop it.

Your data, pictures, settings and backups are kept in %LOCALAPPDATA%\SimonSays, apart from the program: installing a newer one over it, or uninstalling it, keeps them.

4

Check it works

The dashboard opens by itself with a short first setup: your language, bringing in a SimonSays you used before, who can open the dashboard, and OBS. Continue at After installing.

The manual way, with Node.js and Git

Rather run it from source, or keep it in a Git folder? These were the steps before the installer, and still work. Rather not install anything, but no terminal either? SimonSays-Windows-Portable.zip is the installed app unzipped: double-click SimonSays.exe inside.

Install Node.js and Git

Open Windows Terminal or PowerShell (press Start, type terminal, press Enter) and run:

powershell
winget install OpenJS.NodeJS.LTS
winget install Git.Git

No winget? Download the LTS installer from nodejs.org and Git from git-scm.com, and keep every default.

Close the terminal and open a new one, so it sees the new programs. Then check:

powershell
node -v
npm -v
git --version

node -v must say v22 or higher.

Download SimonSays

With Git (recommended), this puts the app in Documents\SimonSays:

powershell
cd $HOME\Documents
git clone https://github.com/Bastian-Alvarado/SimonSays.git
cd SimonSays

Without Git: download SimonSays.zip, the latest release. Right-click it, choose Extract All, and move the SimonSays folder somewhere permanent such as Documents. Then open the folder, right-click an empty space and choose Open in Terminal.

Avoid OneDrive-synced folders if you can. Syncing thousands of small files in node_modules slows the install and can lock files mid-update.

Install the app's dependencies

In the app folder:

powershell
npm install

It installs the server's and the web app's parts in one go, about 300 MB. A few minutes, once. Lines about deprecated packages or vulnerabilities are normal and need nothing from you.

Start it

powershell
npm run serve

The first run builds the web app (under a minute), then starts the server. It is ready when you see:

text
listening on http://0.0.0.0:8081
the stack is now live and does not need a browser open

Leave this window open. It is the app. Minimise it, but don't close it.

From now on, npm start is enough. Use npm run serve again only after updating with Git, so the web app is rebuilt.

Allow it through the firewall

The first time another device connects, Windows asks whether to let Node.js JavaScript Runtime through. Tick Private networks, untick Public, and press Allow. Missed it? Run this in a terminal opened as administrator:

powershell
New-NetFirewallRule -DisplayName "SimonSays" -Direction Inbound -Protocol TCP -LocalPort 8081 -Action Allow -Profile Private

Only needed for phones, other PCs or OBS on another machine. On the same PC, nothing is blocked.

Start it with Windows (optional)

Make a file called start-simonsays.bat in the app folder with this inside:

bat
@echo off
title SimonSays
cd /d "%~dp0"
npm start

Press Win + R, type shell:startup and press Enter. Right-click the .bat file, choose Create shortcut, and move the shortcut into that Startup folder. SimonSays now opens in its own window each time you sign in.

Check it works

Open http://localhost:8081 in your browser, or run:

powershell
curl.exe localhost:8081/api/health

An answer starting {"ok":true means the server is up. Continue at After installing.

Windows problems

  • Windows protected your PC when opening SimonSays-Setup.exe: click More info, then Run anyway. The installer is not signed yet.
  • No icon by the clock: click the ^ beside it, or start SimonSays from the Start menu; started again while it runs, it only opens the dashboard.
  • running scripts is disabled on this system (PowerShell blocks npm): run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once and answer Y. Or use Command Prompt instead.
  • '&&' is not a valid statement separator (Windows PowerShell 5.1): type the commands on separate lines.
  • 'node' is not recognized: open a new terminal after installing Node.js. Still failing? Reinstall Node.js and keep Add to PATH ticked.
  • Port 8081 is already in use: SimonSays is already running in another window. Use that one, or close it first.
  • EPERM or EBUSY during npm install: an antivirus or OneDrive is holding a file. Pause syncing, close editors on the folder, and run npm install again.

Linux

Any 64-bit Linux from the last few years works, desktop or headless: the download brings everything SimonSays needs, Node.js included, and installs it just for you, with no sudo.

1

Download it

Download SimonSays-Linux-x64.tar.gz (64-bit Intel or AMD). On a desktop, SimonSays-x86_64.AppImage is the same in one file: see below.

2

Install it

Unpack it and run its installer, as yourself:

bash
tar -xzf SimonSays-Linux-x64.tar.gz
SimonSays/install.sh

It installs to ~/.local/opt/simonsays, runs as a service of yours that starts by itself, and takes another port when 8081 is in use. On a computer with no screen it listens on your network, so you can open it from another device.

3

Open it

When it is ready it prints the address: http://localhost:8081 on this computer, or the one it shows from another device. Continue at After installing.

bash
systemctl --user stop simonsays       # stop it
journalctl --user -u simonsays -f     # what it says
~/.local/opt/simonsays/uninstall.sh   # remove it (your things are kept)

A home server that should keep it running after you log out: loginctl enable-linger $USER.

The AppImage, on a desktop

Download SimonSays-x86_64.AppImage, make it executable (right-click → Properties → Allow executing as program, or chmod +x SimonSays-x86_64.AppImage), and double-click it. It opens a window to stop it from, and the dashboard in your browser. Your things are kept in ~/.local/share/simonsays, so a newer AppImage finds them.

The manual way, with Node.js and Git

Rather run it from source, or keep it in a Git folder? These were the steps before the download, and still work.

Install Node.js 22+ and Git

Your distribution's own Node.js is often too old, so check first with node -v. Pick the line for your system:

SystemCommands
Ubuntu, Debian, Mint, Pop!_OScurl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - then sudo apt install -y nodejs git
Fedorasudo dnf install nodejs22 git (or nodejs when it is already 22+)
Arch, Manjaro, EndeavourOSsudo pacman -S nodejs npm git
openSUSEsudo zypper install nodejs22 git
Any distro, no root needednvm, below

With nvm (installs Node.js in your home folder):

bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
# close and reopen the terminal, then:
nvm install 22
nvm alias default 22

Then check: node -v must say v22 or higher.

Download SimonSays

bash
cd ~
git clone https://github.com/Bastian-Alvarado/SimonSays.git
cd SimonSays

No Git? curl -L -o SimonSays.zip https://github.com/Bastian-Alvarado/SimonSays/releases/latest/download/SimonSays.zip, then unzip SimonSays.zip && cd SimonSays.

Install and start

bash
npm install
npm run serve

Never run these with sudo. Files created as root break later installs and updates. When you see listening on http://0.0.0.0:8081, the app is running. Leave that terminal open, or set up the service below.

After the first time, start it with npm start.

Open the firewall (only for other devices)

Most desktops have no firewall on by default. If yours does:

bash
# Ubuntu and friends (ufw)
sudo ufw allow 8081/tcp

# Fedora, openSUSE (firewalld)
sudo firewall-cmd --add-port=8081/tcp --permanent
sudo firewall-cmd --reload

Run it as a service (recommended for a home server)

A systemd user service starts SimonSays when the machine boots, restarts it if it crashes, and keeps it running after you log out. First find your Node.js path:

bash
which node

Create ~/.config/systemd/user/simonsays.service, putting that path after ExecStart=:

ini
[Unit]
Description=SimonSays stream automation
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=%h/SimonSays
ExecStart=/usr/bin/node start.js
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target

Then turn it on:

bash
systemctl --user daemon-reload
systemctl --user enable --now simonsays
sudo loginctl enable-linger $USER   # keeps it running when you are logged out

Useful afterwards:

bash
systemctl --user status simonsays     # is it running?
journalctl --user -u simonsays -f     # live log (Ctrl+C to leave)
systemctl --user restart simonsays    # after editing .env

node start.js is exactly what npm start runs. The built-in updater restarts the app by itself, so the service needs no changes when you update from Settings.

No systemd, or just want it in the background? tmux new -s simonsays, run npm start, then press Ctrl+B then D to leave it running. tmux attach -t simonsays brings it back.

Check it works

bash
curl localhost:8081/api/health

An answer starting {"ok":true means it is up. Continue at After installing.

Linux problems

  • No free port between 8081 and 8099: set PORT= in ~/.local/share/simonsays/.env and run install.sh again.
  • The AppImage does nothing when double-clicked: make it executable first (see above).
  • EACCES: permission denied during npm install: the folder or ~/.npm was touched by sudo. Fix with sudo chown -R $USER: ~/SimonSays ~/.npm and run it again without sudo.
  • SyntaxError or Unsupported engine on start: Node.js is older than 22. With nvm, nvm use 22; under systemd, check the ExecStart path points at the new Node.
  • Service starts but can't find node: systemd doesn't load your shell's PATH. Use the full path from which node in ExecStart.
  • EADDRINUSE / port 8081 in use: another copy is running (systemctl --user stop simonsays), or set PORT= in .env.
  • Build killed on a small machine (1 GB RAM or less): add swap, or build on another computer and copy the web/dist folder over.

Android with Termux

An old Android phone on your Wi-Fi can run SimonSays all stream long, while OBS runs on your PC. Termux gives the phone a Linux terminal; the app runs there unchanged. Every native part the app uses (esbuild, Rollup, resvg) ships a ready-made Android ARM build, so nothing is compiled on the phone. The hard part is keeping Android from closing Termux in the background, and steps 4 and 5 deal with that.

You need Android 7 or newer, about 1 GB free, and the phone on the same network as the PC that runs OBS. A 64-bit phone (almost every phone since 2017) is best. Keep it plugged in.

1

Install Termux

Get Termux from F-Droid or the project's GitHub releases (the arm64-v8a APK for most phones). Android asks you to allow installing apps from that source; allow it.

Don't mix sources: Termux and its add-ons (Termux:Boot, Termux:API) must all come from the same place, or they won't work together.

2

Install SimonSays with one command

Open Termux and paste:

bash
curl -fsSL https://github.com/Bastian-Alvarado/SimonSays/releases/latest/download/install-termux.sh | sh

It installs Node.js if the phone has none, downloads the latest release and checks it, takes a port of its own, and starts SimonSays: a few minutes. It never touches a SimonSays already on the phone; for a second copy, put SIMONSAYS_DIR=~/another-folder before sh.

3

Note its address

Open Settings → Wi-Fi, tap your network, and note the IP address, such as 192.168.1.42. You'll use it on the PC:

  • The dashboard: http://192.168.1.42:8081
  • OBS's browser source: http://192.168.1.42:8081/?mode=canvas
  • OBS's dock: http://192.168.1.42:8081/?mode=dock

In your router's settings, give the phone a fixed (reserved) address so it stays the same after a restart. Otherwise OBS loses the app whenever the address changes.

4

Keep Android from stopping it

Android closes background apps to save battery. Do all of these:

  1. Wake lock: pull down Termux's notification and tap Acquire wakelock, or run termux-wake-lock. The CPU then stays awake with the screen off.
  2. Battery: Settings → Apps → Termux → Battery → Unrestricted (sometimes called Don't optimise).
  3. Phone makers' own killers: Samsung, Xiaomi, Huawei, OnePlus and others add their own. Allow Termux to autostart and run in the background, and lock it in the recent-apps list. dontkillmyapp.com has steps for each brand.
  4. Android 12 and newer may kill apps with many processes (the phantom process killer). On Android 14+, open Developer options and turn on Disable child process restrictions. On Android 12 and 13, run from a PC with ADB: adb shell device_config put activity_manager max_phantom_processes 2147483647.
5

Start it when the phone boots

Install Termux:Boot from the same place as Termux and open it once: the command already left SimonSays's start-up in ~/.termux/boot.

6

Sign in to Twitch on the phone itself

Twitch only accepts a plain http:// sign-in address for localhost. Do the Twitch sign-in once in the phone's own browser at http://localhost:8081, with http://localhost:8081/ as the redirect URL in your Twitch app. Every other device then shares that sign-in. The rest of the setup can be done from the PC.

7

Point the app at OBS on your PC

In OBS (on the PC): Tools → WebSocket Server Settings, tick Enable WebSocket server, and press Show Connect Info. On the app's Connections screen, use the PC's IP address (not localhost), port 4455 and that password. If Windows asks, allow OBS through the firewall on private networks.

Update Termux and install Node.js and Git

Open Termux and run:

bash
pkg update && pkg upgrade -y
pkg install -y nodejs-lts git
node -v

Press Enter to accept the default when it asks about config files. node -v must say v22 or higher; if nodejs-lts is older, run pkg install nodejs instead (the current release).

Download SimonSays into Termux's home

bash
cd ~
git clone https://github.com/Bastian-Alvarado/SimonSays.git
cd SimonSays

Keep it in Termux's home folder (~). Your phone's shared storage (/sdcard, Downloads) doesn't allow the links and permissions node_modules needs, and installing there fails.

Install and start

bash
npm install
npm run serve

On a phone this takes longer than on a PC: allow 5 to 15 minutes for npm install and a few minutes for the first build. Keep the screen on and Termux in front while it runs. When you see listening on http://0.0.0.0:8081, it's running.

After the first time, npm start is enough.

Keep it running in the background

Run the app inside tmux, so it survives Termux's window being closed by mistake:

bash
pkg install -y tmux
tmux new -s simonsays
cd ~/SimonSays && npm start

Press Ctrl+B then D to leave it running (Termux's extra-keys row has CTRL). tmux attach -t simonsays brings it back.

Start it when the phone boots (optional)

Install Termux:Boot from the same place as Termux and open it once. Then in Termux:

bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/simonsays <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
cd ~/SimonSays
npm start > ~/simonsays.log 2>&1
EOF
chmod +x ~/.termux/boot/simonsays

After a restart, SimonSays comes up on its own. tail -f ~/simonsays.log shows its log.

Termux problems

  • It says the folder is already there: SimonSays is installed; it updates itself from Settings → About.
  • Repository is under maintenance or down: run termux-change-repo, pick a mirror near you, then pkg update again.
  • CANNOT LINK EXECUTABLE or library errors after an update: run pkg upgrade -y. Termux needs all its packages at the same level.
  • npm install fails on /sdcard with EPERM or symlink: the app is in shared storage. Move it to ~ (the manual way).
  • The app stops after the screen turns off: the wake lock is missing or the battery setting is still optimised (step 4).
  • [Process completed (signal 9)]: Android's phantom process killer. See step 4.4.
  • Build runs out of memory: close other apps and run npm run build again. Or build on a PC and copy the web/dist folder into the phone's ~/SimonSays/web/.

After installing

The rest of the setup happens in the app, the same on every system. Its home screen lists the steps still to do and ticks them off. Guides → Start here has click-by-click walkthroughs for each platform, in English and Spanish.

  1. Open it. Go to http://localhost:8081 on the machine running it, or http://<its-ip>:8081 from another device.
  2. Connect where you stream (Connections screen). Twitch needs an app of your own, made once:
    1. Turn on two-factor authentication on your Twitch account (Settings → Security and Privacy).
    2. At dev.twitch.tv/console/apps press Register Your Application. Any name; OAuth Redirect URL http://localhost:8081/; category Chat Bot.
    3. Press Manage, copy the Client ID, paste it on the Connections screen and press Login with Twitch, on the machine running SimonSays.
  3. Connect OBS. In OBS: Tools → WebSocket Server Settings, tick Enable WebSocket server, press Show Connect Info. In the app: host localhost (or the OBS PC's IP), port 4455, and the password.
  4. Put the stream in OBS. Add a Browser source, 1920 × 1080, with the address copied from the app's Overlays screen (http://localhost:8081/?mode=canvas). It draws everything: chat, alerts, bars, timers and avatars.
  5. Add the dock. In OBS: Docks → Custom Browser Docks, with http://localhost:8081/?mode=dock.
  6. Make it yours: a layout or a theme from Looks, the alerts you want, commands and actions.
  7. Before anyone else can reach it: switch on Settings → Sign-in. Then only you and your Twitch channel's moderators can open the dashboard. Do this before exposing it beyond your home network.

Once sign-in is on, copy OBS's addresses again from the app: they then carry the page key OBS needs.

Settings in a file (optional)

Everything can be set in the app. To set the port, the listening address or keys in a file instead, copy the example into the app folder and edit it:

bash
cp server/.env.example .env        # Windows: copy server\.env.example .env

Lines left blank are ignored, and real environment variables win over the file (PORT=9000 npm start). Restart the app after editing. The most useful lines:

Keep .env in the app folder itself, not inside server/. Updates never touch it there.

Updating, backups and removing

Updating

The app updates itself on every system. It checks GitHub once a day, and Settings → About shows when a new version is out, with what's new. Update now downloads it, checks it arrived whole, backs up data/ to backups/, and restarts into it in a few seconds. If the new version won't start, it goes back to the one you had. It never updates on its own, and never while OBS is streaming or recording.

Your data is also backed up every day and before every update: Settings → Data Management → Automatic backups lists the backups, the newest seven of each kind, and puts any of them back.

Installed copies (Windows and Linux) take a package made for them, with everything in it; a copy started with npm start or npm run serve installs what changed with npm. npm run dev has no updater.

Prefer Git? From the app folder:

bash
git pull
npm install
npm run serve

A newer copy from Git wins over an older version installed from Settings.

What to back up

Everything that is yours lives in one folder: %LOCALAPPDATA%\SimonSays installed on Windows, ~/.local/share/simonsays installed on Linux or with the AppImage, and the app folder itself for Termux, Git and zip copies. In it:

PathHolds
data/Commands, actions, alerts, layouts, XP, connections and every setting
assets/Sounds, pictures and fonts you uploaded
.envYour file settings, if you made one

The app can also export its configuration as one file from Settings → Export Configuration. To move to another machine, install SimonSays there, stop it, copy those three in, and start it. On the same machine, from a Git or zip copy to an installed one: Settings → About → Bring in my existing SimonSays copies it all in.

Removing it

  • Windows, installed: Settings → Apps → SimonSays → Uninstall. It stops SimonSays first, and asks before deleting your data.
  • Linux, installed: ~/.local/opt/simonsays/uninstall.sh (add --purge to delete your data too). The AppImage: delete the file.
  • Android (Termux): kill $(cat ~/SimonSays/simonsays.pid), delete ~/.termux/boot/simonsays-SimonSays, then the SimonSays folder.
  • Git or zip copies: close the server window, or systemctl --user disable --now simonsays for a service you made yourself, or tmux kill-session -t simonsays in Termux; remove what starts it; back up data/ and assets/ if you might come back, then delete the app folder.
  • Node.js and Git can stay; other programs may use them.

La primera vez construye la app web (menos de un minuto) y luego inicia el servidor. Está lista cuando ves:

Deja esta ventana abierta. Es la app. Puedes minimizarla, pero no cerrarla.

De aquí en adelante basta con npm start. Vuelve a usar npm run serve solo después de actualizar con Git, para que la app web se reconstruya.

Permítela en el firewall

La primera vez que otro dispositivo se conecte, Windows pregunta si deja pasar a Node.js JavaScript Runtime. Marca Redes privadas, desmarca Públicas y pulsa Permitir. ¿Te lo saltaste? Ejecuta esto en una terminal abierta como administrador:

powershell
New-NetFirewallRule -DisplayName "SimonSays" -Direction Inbound -Protocol TCP -LocalPort 8081 -Action Allow -Profile Private

Solo hace falta para teléfonos, otros PC u OBS en otra máquina. En el mismo PC no se bloquea nada.

Problemas en Windows

  • Windows protegió tu equipo al abrir SimonSays-Setup.exe: haz clic en Más información y luego en Ejecutar de todas formas. El instalador aún no está firmado.
  • No hay icono junto al reloj: haz clic en la ^ de al lado, o abre SimonSays desde el menú Inicio; abierto de nuevo mientras corre, solo abre el panel.
  • running scripts is disabled on this system (PowerShell bloquea npm): ejecuta una vez Set-ExecutionPolicy -Scope CurrentUser RemoteSigned y responde S (o Y). O usa el Símbolo del sistema en su lugar.
  • '&&' is not a valid statement separator (Windows PowerShell 5.1): escribe los comandos en líneas separadas.
  • 'node' is not recognized: abre una terminal nueva después de instalar Node.js. ¿Sigue fallando? Reinstala Node.js con Add to PATH marcado.
  • Port 8081 is already in use: SimonSays ya está corriendo en otra ventana. Usa esa, o ciérrala primero.
  • EPERM o EBUSY durante npm install: un antivirus u OneDrive tiene un archivo tomado. Pausa la sincronización, cierra los editores abiertos en la carpeta y vuelve a ejecutar npm install.

Como servicio (recomendado en un servidor de casa)

Un servicio de usuario de systemd inicia SimonSays al arrancar la máquina, lo reinicia si se cae y lo mantiene corriendo aunque cierres sesión. Primero busca la ruta de Node.js:

bash
which node

Crea ~/.config/systemd/user/simonsays.service y pon esa ruta después de ExecStart=:

ini
[Unit]
Description=SimonSays stream automation
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=%h/SimonSays
ExecStart=/usr/bin/node start.js
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target

Luego actívalo:

bash
systemctl --user daemon-reload
systemctl --user enable --now simonsays
sudo loginctl enable-linger $USER   # sigue corriendo aunque cierres sesión

Útil después:

bash
systemctl --user status simonsays     # ¿está corriendo?
journalctl --user -u simonsays -f     # registro en vivo (Ctrl+C para salir)
systemctl --user restart simonsays    # después de editar .env

node start.js es exactamente lo que ejecuta npm start. El actualizador integrado reinicia la app por sí mismo, así que el servicio no necesita cambios cuando actualizas desde Ajustes.

¿Sin systemd, o solo lo quieres en segundo plano? tmux new -s simonsays, ejecuta npm start y pulsa Ctrl+B y luego D para dejarlo corriendo. tmux attach -t simonsays lo trae de vuelta.

Comprueba que funciona

bash
curl localhost:8081/api/health

Una respuesta que empieza con {"ok":true significa que está funcionando. Sigue en Después de instalar.

Problemas en Linux

  • No hay un puerto libre entre 8081 y 8099: pon PORT= en ~/.local/share/simonsays/.env y vuelve a ejecutar install.sh.
  • La AppImage no hace nada al hacer doble clic: hazla ejecutable primero (mira arriba).
  • EACCES: permission denied durante npm install: la carpeta o ~/.npm se tocaron con sudo. Arréglalo con sudo chown -R $USER: ~/SimonSays ~/.npm y vuelve a ejecutarlo sin sudo.
  • SyntaxError o Unsupported engine al iniciar: Node.js es anterior a 22. Con nvm, nvm use 22; con systemd, revisa que la ruta de ExecStart apunte al Node nuevo.
  • El servicio arranca pero no encuentra node: systemd no carga el PATH de tu shell. Usa la ruta completa de which node en ExecStart.
  • EADDRINUSE / el puerto 8081 está en uso: hay otra copia corriendo (systemctl --user stop simonsays), o define PORT= en .env.
  • La compilación se corta en una máquina pequeña (1 GB de RAM o menos): agrega swap, o compila en otro computador y copia la carpeta web/dist.

Android con Termux

Un teléfono Android antiguo conectado a tu Wi-Fi puede correr SimonSays todo el directo, mientras OBS corre en tu PC. Termux le da al teléfono una terminal de Linux, y la app corre ahí sin cambios. Todas las partes nativas que usa la app (esbuild, Rollup, resvg) traen una versión lista para Android ARM, así que no se compila nada en el teléfono. Lo difícil es evitar que Android cierre Termux en segundo plano, y de eso se encargan los pasos 4 y 5.

Necesitas Android 7 o más nuevo, alrededor de 1 GB libre, y el teléfono en la misma red que el PC donde corre OBS. Lo mejor es un teléfono de 64 bits (casi todos desde 2017). Déjalo enchufado.

1

Instala Termux

Descarga Termux desde F-Droid o desde las versiones en GitHub del proyecto (el APK arm64-v8a para la mayoría de los teléfonos). Android te pedirá permitir instalar apps desde ese origen; permítelo.

No mezcles orígenes: Termux y sus complementos (Termux:Boot, Termux:API) tienen que venir todos del mismo lugar, o no funcionan juntos.

2

Instala SimonSays con un comando

Abre Termux y pega:

bash
curl -fsSL https://github.com/Bastian-Alvarado/SimonSays/releases/latest/download/install-termux.sh | sh

Instala Node.js si el teléfono no lo tiene, descarga la última versión y la comprueba, usa un puerto propio e inicia SimonSays: unos minutos. Nunca toca un SimonSays que ya esté en el teléfono; para una segunda copia, pon SIMONSAYS_DIR=~/otra-carpeta antes de sh.

3

Anota su dirección

Abre Ajustes → Wi-Fi, toca tu red y anota la dirección IP, por ejemplo 192.168.1.42. La usarás en el PC:

  • El panel: http://192.168.1.42:8081
  • La fuente de navegador de OBS: http://192.168.1.42:8081/?mode=canvas
  • El dock de OBS: http://192.168.1.42:8081/?mode=dock

En la configuración de tu router, dale al teléfono una dirección fija (reservada) para que no cambie después de un reinicio. Si no, OBS pierde la app cada vez que cambia la dirección.

4

Evita que Android lo detenga

Android cierra las apps en segundo plano para ahorrar batería. Haz todo esto:

  1. Wake lock: baja la notificación de Termux y toca Acquire wakelock, o ejecuta termux-wake-lock. Así el procesador sigue despierto con la pantalla apagada.
  2. Batería: Ajustes → Aplicaciones → Termux → Batería → Sin restricciones (a veces No optimizar).
  3. Los cierres propios de cada marca: Samsung, Xiaomi, Huawei, OnePlus y otras agregan los suyos. Permite que Termux se inicie solo y corra en segundo plano, y bloquéalo en la lista de apps recientes. dontkillmyapp.com tiene los pasos para cada marca.
  4. Android 12 y más nuevos pueden cerrar apps con muchos procesos (el phantom process killer). En Android 14+, abre las Opciones de desarrollador y activa Desactivar restricciones de procesos secundarios. En Android 12 y 13, ejecuta desde un PC con ADB: adb shell device_config put activity_manager max_phantom_processes 2147483647.
5

Que arranque con el teléfono

Instala Termux:Boot desde el mismo sitio que Termux y ábrelo una vez: el comando ya dejó el arranque de SimonSays en ~/.termux/boot.

6

Inicia sesión en Twitch en el propio teléfono

Twitch solo acepta una dirección http:// simple para localhost. Inicia sesión en Twitch una vez desde el navegador del propio teléfono en http://localhost:8081, con http://localhost:8081/ como URL de redirección en tu app de Twitch. Todos los demás dispositivos comparten esa sesión. El resto de la configuración puedes hacerla desde el PC.

7

Apunta la app a OBS en tu PC

En OBS (en el PC): Herramientas → Configuración del servidor WebSocket (Tools → WebSocket Server Settings), marca Habilitar servidor WebSocket y pulsa Mostrar información de conexión. En la pantalla Conexiones de la app, usa la dirección IP del PC (no localhost), el puerto 4455 y esa contraseña. Si Windows pregunta, permite OBS en el firewall para redes privadas.

A mano, con Node.js y Git

¿Prefieres hacerlo a mano, o con Git? Estos eran los pasos antes del comando, y siguen funcionando.

Actualiza Termux e instala Node.js y Git

Abre Termux y ejecuta:

bash
pkg update && pkg upgrade -y
pkg install -y nodejs-lts git
node -v

Pulsa Enter para aceptar la opción por defecto cuando pregunte por archivos de configuración. node -v tiene que decir v22 o más; si nodejs-lts es más antiguo, ejecuta pkg install nodejs (la versión actual).

Descarga SimonSays en la carpeta personal de Termux

bash
cd ~
git clone https://github.com/Bastian-Alvarado/SimonSays.git
cd SimonSays

Déjalo en la carpeta personal de Termux (~). El almacenamiento compartido del teléfono (/sdcard, Descargas) no permite los enlaces y permisos que necesita node_modules, y la instalación falla ahí.

Instala e inicia

bash
npm install
npm run serve

En un teléfono tarda más que en un PC: calcula entre 5 y 15 minutos para npm install y algunos minutos para la primera compilación. Mantén la pantalla encendida y Termux al frente mientras corre. Cuando veas listening on http://0.0.0.0:8081, está funcionando.

Después de la primera vez, basta con npm start.

Que siga corriendo en segundo plano

Corre la app dentro de tmux, para que sobreviva si cierras la ventana de Termux por error:

bash
pkg install -y tmux
tmux new -s simonsays
cd ~/SimonSays && npm start

Pulsa Ctrl+B y luego D para dejarla corriendo (la fila de teclas extra de Termux tiene CTRL). tmux attach -t simonsays la trae de vuelta.

Que arranque al encender el teléfono (opcional)

Instala Termux:Boot desde el mismo lugar que Termux y ábrelo una vez. Luego, en Termux:

bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/simonsays <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
cd ~/SimonSays
npm start > ~/simonsays.log 2>&1
EOF
chmod +x ~/.termux/boot/simonsays

Después de un reinicio, SimonSays arranca sola. tail -f ~/simonsays.log muestra su registro.

Problemas en Termux

  • Dice que la carpeta ya existe: SimonSays está instalado; se actualiza solo desde Ajustes → Acerca de.
  • Repository is under maintenance or down: ejecuta termux-change-repo, elige un espejo cercano y vuelve a ejecutar pkg update.
  • CANNOT LINK EXECUTABLE o errores de bibliotecas después de actualizar: ejecuta pkg upgrade -y. Termux necesita todos sus paquetes al mismo nivel.
  • npm install falla en /sdcard con EPERM o symlink: la app está en el almacenamiento compartido. Muévela a ~ (a mano).
  • La app se detiene al apagarse la pantalla: falta el wake lock o la batería sigue optimizada (paso 4).
  • [Process completed (signal 9)]: el phantom process killer de Android. Mira el paso 4.4.
  • La compilación se queda sin memoria: cierra otras apps y vuelve a ejecutar npm run build. O compila en un PC y copia la carpeta web/dist a ~/SimonSays/web/ en el teléfono.

Después de instalar

El resto de la configuración se hace en la app y es igual en todos los sistemas. Su pantalla de inicio muestra los pasos que faltan y los va marcando. Guías → Empieza aquí tiene instrucciones clic a clic para cada plataforma, en español e inglés.

  1. Ábrela. Ve a http://localhost:8081 en la máquina donde corre, o a http://<su-ip>:8081 desde otro dispositivo.
  2. Conecta donde transmites (pantalla Conexiones). Twitch necesita una app propia, creada una sola vez:
    1. Activa la verificación en dos pasos en tu cuenta de Twitch (Configuración → Seguridad y privacidad).
    2. En dev.twitch.tv/console/apps pulsa Register Your Application. Cualquier nombre; OAuth Redirect URL http://localhost:8081/; categoría Chat Bot.
    3. Pulsa Manage, copia el Client ID, pégalo en la pantalla Conexiones y pulsa Iniciar sesión con Twitch, en la máquina donde corre SimonSays.
  3. Conecta OBS. En OBS: Herramientas → Configuración del servidor WebSocket (Tools → WebSocket Server Settings), marca Habilitar servidor WebSocket y pulsa Mostrar información de conexión. En la app: host localhost (o la IP del PC con OBS), puerto 4455 y la contraseña.
  4. Pon el directo en OBS. Agrega una fuente de Navegador, de 1920 × 1080, con la dirección copiada desde la pantalla Overlays de la app (http://localhost:8081/?mode=canvas). Dibuja todo: chat, alertas, barras, temporizadores y avatares.
  5. Agrega el dock. En OBS: Paneles → Paneles de navegador personalizados (Docks → Custom Browser Docks), con http://localhost:8081/?mode=dock.
  6. Hazla tuya: un layout o un tema de Looks, las alertas que quieras, comandos y acciones.
  7. Antes de que otros puedan entrar: activa Ajustes → Inicio de sesión. Así solo tú y los moderadores de tu canal de Twitch pueden abrir el panel. Hazlo antes de exponerla fuera de tu red de casa.

Con el inicio de sesión activado, vuelve a copiar las direcciones de OBS desde la app: desde entonces llevan la clave de página que OBS necesita.

Ajustes en un archivo (opcional)

Todo se puede configurar en la app. Para fijar el puerto, la dirección donde escucha o las claves en un archivo, copia el ejemplo a la carpeta de la app y edítalo:

bash
cp server/.env.example .env        # Windows: copy server\.env.example .env

Las líneas vacías se ignoran, y las variables de entorno reales ganan sobre el archivo (PORT=9000 npm start). Reinicia la app después de editarlo. Las líneas más útiles:

AjustePor defectoQué hace
PORT8081El puerto donde se sirve todo. Si lo cambias, actualiza todas las direcciones de OBS y la URL de redirección de Twitch.
HOST0.0.0.00.0.0.0 deja entrar a otros dispositivos de la red; 127.0.0.1 la limita a esta máquina.
DATA_DIRdataDónde se guardan tus comandos, alertas, XP y ajustes.
ASSETS_DIRassetsDónde se guardan los sonidos e imágenes que subes.
AUTO_STARTtrueVuelve a conectar tus plataformas al iniciar.
OBS_HOST, OBS_PORT, OBS_PASSWORDlocalhost, 4455, vacíoLa conexión con OBS, si prefieres no escribirla en la app.
LOG_LEVELinfodebug para más detalle cuando algo falla.

Guarda .env en la carpeta de la app, no dentro de server/. Las actualizaciones nunca lo tocan ahí.

Actualizar, respaldar y desinstalar

Actualizar

La app se actualiza sola en todos los sistemas. Revisa GitHub una vez al día, y Ajustes → Acerca de muestra cuando hay una versión nueva, con sus novedades. Actualizar ahora la descarga, comprueba que llegó completa, respalda data/ en backups/ y se reinicia en ella en unos segundos. Si la versión nueva no arranca, vuelve a la que tenías. Nunca se actualiza por su cuenta, ni mientras OBS está transmitiendo o grabando.

Tus datos también se respaldan cada día y antes de cada actualización: Ajustes → Gestión de Datos → Respaldos automáticos muestra los respaldos, los siete más recientes de cada tipo, y restaura cualquiera de ellos.

Las copias instaladas (Windows y Linux) toman un paquete hecho para ellas, con todo dentro; una copia iniciada con npm start o npm run serve instala lo que cambió con npm. npm run dev no tiene actualizador.

¿Prefieres Git? Desde la carpeta de la app:

bash
git pull
npm install
npm run serve

Una copia más nueva desde Git gana sobre una versión más antigua instalada desde Ajustes.

Qué respaldar

Todo lo tuyo vive en una carpeta: %LOCALAPPDATA%\SimonSays instalada en Windows, ~/.local/share/simonsays instalada en Linux o con la AppImage, y la propia carpeta de la app en Termux y en copias de Git o zip. Dentro:

RutaContiene
data/Comandos, acciones, alertas, layouts, XP, conexiones y todos los ajustes
assets/Los sonidos, imágenes y fuentes que subiste
.envTus ajustes en archivo, si creaste uno

La app también puede exportar su configuración en un archivo desde Ajustes → Exportar configuración. Para pasar a otra máquina, instala SimonSays allí, detenlo, copia esos tres y vuelve a iniciarlo. En la misma máquina, de una copia de Git o zip a una instalada: Ajustes → Acerca de → Traer mi SimonSays de antes lo copia todo.

Desinstalar

  • Windows, instalada: Configuración → Aplicaciones → SimonSays → Desinstalar. Primero detiene SimonSays, y pregunta antes de borrar tus datos.
  • Linux, instalada: ~/.local/opt/simonsays/uninstall.sh (añade --purge para borrar también tus datos). La AppImage: borra el archivo.
  • Android (Termux): kill $(cat ~/SimonSays/simonsays.pid), borra ~/.termux/boot/simonsays-SimonSays y luego la carpeta SimonSays.
  • Copias de Git o zip: cierra la ventana del servidor, o systemctl --user disable --now simonsays para un servicio que hiciste tú, o tmux kill-session -t simonsays en Termux; quita lo que lo inicia; respalda data/ y assets/ por si vuelves, y borra la carpeta de la app.
  • Node.js y Git pueden quedarse; otros programas pueden usarlos.
